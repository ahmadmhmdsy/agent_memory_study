# agent_memory_study

[English](README.md) | **العربية**

**كيف ينبغي لوكيل برمجي أن يتذكّر مشروعًا عبر جلسات متعددة، وما أرخص طريقة لذلك تظل ناجحة؟**

يضم هذا المستودع أداة التشغيل، ونحو 1,000 ملف مهام، وشيفرة التحليل التي قامت عليها ثلاث دراسات مسجّلة مسبقًا عن الوكلاء البرمجيين متعددي الجلسات. نفّذت الدراسات معًا نحو 1,750 وحدة وكيل مُقيَّمة (الوحدة مشروع واحد بكل جلساته) داخل بيئات Docker معزولة. الوكيل هو `CodeAgent` من مكتبة smolagents-ts. يعمل على مشروع عبر جلسات كثيرة، ويحتفظ بالذاكرة بين الجلسات بإحدى 12 طريقة: بلا ذاكرة، أو ملف ملاحظات، أو «حزمة سياق» منظّمة، أو إعادة تشغيل النص الكامل للجلسات السابقة، وغيرها. ثم تتحقق اختبارات مخفية من أن الشيفرة تعمل ومن أن الوكيل تذكّر الحقائق من الجلسات السابقة.

## أبرز النتائج

| الدراسة | السؤال | الجواب |
|---|---|---|
| **R-013**: ‏24 مهمة قصيرة × 5 حالات × 3 تكرارات | هل تساعد الذاكرة أصلًا؟ | **نعم، وبفارق كبير.** تتفوق حزمة السياق على غياب الذاكرة بـ **+56.9 نقطة** في نسبة النجاح (قيمة p بعد تصحيح Holm ‏= 0.0002). في المهام القصيرة تقترب كل حالات الذاكرة من السقف (86–96%). |
| **R-014**: مشاريع من 8 جلسات فيها 12 حقيقة متغيّرة | هل تتفوق الحزمة على الملاحظات البسيطة في مشروع طويل؟ | الذاكرة مقابل غيابها: **+26 إلى +29 نقطة** في درجة الحقائق (C0 ‏68 ← C1 ‏95، C2 ‏97، C2g ‏97، C3 ‏96). الحزمة والملاحظات متعادلتان، فلم يفرّق المشروع الطويل بينهما. |
| **R-015**: ‏12 مسار ذاكرة، 3 أحجام مشاريع، 48 مشروعًا | أي مسار ذاكرة هو **الأرخص لكل نجاح**؟ | **إعادة تشغيل النص الكامل (C3) تفوز في كل المستويات.** تبلغ إجمالًا **93.1% نجاحًا بتكلفة 0.181$ لكل نجاح**، مقابل 0.224$ للحزمة الكاملة. وفي المستوى المتقدم تتقدم إعادة التشغيل في النجاح بـ +20 نقطة (95.0% مقابل 75.0%). |

سبب مرجّح لرخص إعادة التشغيل: يخزّن المزوّد البادئة المُعادة مؤقتًا (cache)، ويقضي الوكيل خطوات أقل في إعادة بناء السياق. لكن تحت ميزانية صارمة من *الرموز* (tokens) تنقلب المعادلة: في ذراع الميزانية المحدودة الجزئية تبقى إعادة التشغيل متقدمة في المشاريع البسيطة والمتوسطة، أما في المشاريع المتقدمة فتنفد ميزانيتها أولًا.

## مسارات الذاكرة (R-015)

| المسار | الذاكرة بين الجلسات |
|---|---|
| C0 | لا شيء (الحد الأدنى) |
| C1 / C1t | ملف `NOTES.md` حر / ملاحظات بقالب ثابت |
| C2 | حزمة السياق الكاملة (`AGENTS.md`، المهام، التسليم، القرارات) |
| C2−t / C2−h / C2−d | الحزمة دون المهام / التسليم / القرارات (دراسات حذف) |
| C2a | ملف `AGENTS.md` وحده |
| C2x | الحزمة مع ملف مشتِّت لا صلة له |
| C3 | إعادة تشغيل النص الكامل للجلسات |
| C3c | إعادة التشغيل مع ضغط النص بعد حدٍّ معيّن للحجم |
| C4 | ملاحظات تفاضلية على طريقة ACE |

جرت الدراسة على ثلاث مراحل:
1. **الفرز:** ‏12 مسارًا × 8 مشاريع × تكراران. نجت المسارات C0 وC2 وC3 وC2-h. الملفات المشتِّتة رفعت التكلفة دون أي مكسب، وحذف ملف المهام كلّف 19 نقطة.
2. **التأكيد:** ‏4 مسارات × 48 مشروعًا × 3 تكرارات، أو 5 تكرارات حيث بقي مجال الثقة واسعًا.
3. **أذرع الميزانية:** توقفت مبكرًا حين سُحب النموذج المجاني، فهي مُبلَّغ عنها جزئيًا ودون ترتيب.

## كيف يعمل

</div>

```
harness/run.mjs ─┬─ one Docker Jupyter sandbox per session (1 CPU, 1 GB)
                 ├─ harness/model.mjs   OpenAI-compatible client, retries, per-call usage log
                 ├─ harness/prompts.mjs session prompts and memory conditions
                 └─ templates/          notes, pack and ablation templates
tasks/            project generators + hidden tests (simple T*, intermediate L*, advanced A*)
harness/analysis/ paired bootstrap, ranking rule, drop rule, cost pricing (r015.py, scored014.py, sig.py)
docs/experiments/ the pre-registrations, stage logs and results (R-013, R-014, R-015, R-017)
```

**الصرامة المنهجية:**
- سُجّلت كل دراسة مسبقًا قبل قراءة أي نتيجة مُقيَّمة، وأي تغيير لاحق هو تعديل مؤرَّخ.
- تستخدم الإحصاءات bootstrap مزدوجًا على مستوى المشاريع (10,000 إعادة معاينة، بذرة ثابتة) مع مجالات ثقة 95%.
- تُحسب التكلفة لكل استدعاء، مع تسعير منفصل لرموز الإدخال والإخراج والرموز المخزّنة مؤقتًا. وتشمل الإجماليات الجلسات الفاشلة أيضًا.
- أعطال البنية التحتية (حدود المعدّل، أخطاء Docker) يُعاد تشغيلها مرة واحدة ولا تُحسب أبدًا فشلًا في المهمة.
- تمر المشاريع الجديدة بفحوص ثابتة (`tasks/check_facts.py` و`check_long.py`) كي لا يسأل أي اختبار مخفي عن حقيقة لم تُذكر في أي موجّه.

## التشغيل

تحتاج إلى Node 20+‎، وPython 3.11+‎ مع numpy، وDocker، ونسخة مبنية من مكتبة smolagents-ts. تشير أداة التشغيل حاليًا إلى مسارات محلية: يحوي `harness/model.mjs` مسار المكتبة وموقع ملف `.env` الذي فيه `OPENCODE_API_KEY`. عدّل الاثنين بما يناسب إعدادك.

</div>

```bash
docker build -t r013-sandbox:1 docker/
node harness/run.mjs --out runs/demo --tasks L05 --conds C0,C2,C3 --reps 1 --max-steps 20
python harness/analysis/r015.py runs/demo
node harness/sweep.mjs   # removes any leftover sandbox containers
```

مخرجات التشغيل (`runs/`، نحو 2 غيغابايت) ليست في المستودع.

## الحدود

- استخدمت كل دراسة نموذجًا مجانيًا واحدًا: LongCat في R-013، وMiniMax M3.1 Flash في R-014 وR-015. قد لا تنطبق النتائج على نماذج أخرى.
- التكاليف بالدولار محسوبة بسعر القائمة للنموذج المدفوع المماثل.
- في المستوى المتقدم أبقى التفاوت بين المشاريع مجال الثقة الحاسم أوسع من هامش الخمس نقاط، حتى بعد 5 تكرارات.

راجع `docs/experiments/` للسجلات الكاملة (بالإنجليزية).
